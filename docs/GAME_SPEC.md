## 1. ゲームの骨格

サッカー選手を **5歳4月** から育てる放置系・周回系の育成ゲーム。

```
5歳4月スタート
  │
  ├─ 毎ティック = ゲーム内1ヶ月（tickMs = max(125, 1000/gameSpeed)）
  │
  ├─ 練習でステータスを上げる（手動 or AUTO）
  ├─ 公式戦が自動でシミュレートされる
  ├─ 総合力が reqRating を超えるとカテゴリが上がる（全19段階）
  │
  ├─ 7 / 12 / 15 / 18歳の4月に【進路選択】
  │
  └─ 引退 → 【タイムリープ】 → 継承結晶を持って5歳へ戻る
       └─ さらに上位転生（Ascension）が第2〜第5段階まである
```

## 2. ステータスと成長

### 2-1. 4つの能力

`tec`（技術）/ `phy`（身体）/ `iq`（戦術）/ `sht`（決定力）。
**総合力 = 4つの単純合計**（`getTotalRating` / 2,166行）。

### 2-2. 能力上限（cap）

成長の主軸。`computeIndividualStatCaps`（2,230行・**位置引数17個**）で算出。

```
上限プール → POSITIONS[pos].capRatio × BODY_TYPES[body].capMult で4能力へ配分
```

**年齢リミッター**（この設計が「頭脳は大人、体は子供」を作っている）:

| 対象 | 年齢 | 係数 |
|---|---|---|
| 身体系 | 8歳未満 | 0.14 |
| 身体系 | 8–11歳 | 0.2 |
| 身体系 | 12–14歳 | 0.36 |
| 身体系 | 15–17歳 | 0.65 |
| 身体系 | 18歳以上 | 1.0 |
| 頭脳(iq) | 12歳未満 | 0.72 |
| 頭脳(iq) | 12–14歳 | 0.85 |
| 頭脳(iq) | 15歳以上 | 1.0 |

### 2-3. 上限超過時の逓減（`applyStatGrowth` / 2,408行）

上限を超えても成長は止まらず、超過分が減衰する。

```
超過分の基礎係数 = 1/18（通常） または 1/6（「限界突破の極意書」所持時）
さらに  diminishing = 1 / (1 + excessRatio * 7.0)
```

> 🐞 **この3行が `getDrillEffectiveStats`（2,573付近）にも完全コピーされている。**
> しかも予測側だけ `!isBtBanned`（チャレンジ中のブレイクスルー封印）を見ていて、
> 実際の加算側（`applyStatGrowth` / 2,411行）は見ていない。
> → CH7「記憶封印」/ CH8「無一文」中は、**UIの予想成長量が 1/18 で表示されるのに
> 実際の加算は 1/6 で走る**。縛りの意味も消えている。

### 2-4. ライフステージ（`getCareerStageInfo` / 2,121行）

| ステージ | 年齢 | 成長倍率 |
|---|---|---|
| キッズ期 | 〜11 | ×1.04 |
| ユース期 | 〜17 | ×1.16 |
| 若手飛躍期 | 〜23 | ×1.25 |
| プロ黄金期 | 〜31 | ×1.1 |
| 衰え期 | 32〜 | `max(0.4, 1 - (age-31) * 0.06)` |

> ⚠️ **確認が必要**: 衰え減衰を緩和する永続報酬（ED5「-30%」/ CH5「-45%」/
> `king_eternal_dna`「-Lv×10%」/ `secret_veteran_iron`「半減」/ `fused_eternal_king`「65%カット」）を
> `getCareerStageInfo` は一切受け取っていない。試合戦力側だけに掛かる仕様なのか、
> 成長減衰への実装漏れなのか、判断がついていない。

### 2-5. 習慣熟練度

`mastery[drillId] / 30` で Lv。`getHabitMilestoneMult`（2,154行）が
Lv 5/10/20/35/50 で倍率の階段を作る（最大 `(1 + Lv×0.025) × 2.6`。CH7達成で ×1.6）。

### 2-6. 身長（`getDynamicHeight` / 2,135行）

5歳 108cm から 18歳で体格タイプの目標身長へ `pow(progress, 0.85)` で収束。

## 4. 進路選択（4,262行〜 `advanceOneMonth` 内）

**4月のみ**発生。`triggeredEvents` にフラグが立ち、一度きり。

| 年齢 | 選択肢数 | フラグ | 条件 |
|---|---|---|---|
| 7歳 | 3 | `age7` | `categoryId < 9` |
| 12歳 | 5 | `age12` | `categoryId < 9` |
| 15歳 | 5 | `age15` | `categoryId < 9` |
| 18歳 | 5 | `age18` | `categoryId < 9` |

選択肢オブジェクトの形（`opts7` 等。4,610行付近）:

```js
{
  id: 'jr_local',                    // careerPath に入る
  shortTitle: '地元ジュニア少年団',    // careerPathLabel
  clubTitle: '蒼空FCジュニア',        // clubName
  title: '…へ入団（普通の弱小チーム）',
  unlocked: true,                    // false ならグレーアウト
  reqText: '条件なし（誰でも入団可能）',
  perkSummary: '体力回復+4%/Lv・…',
  genomeId: 'jr_local_dna',
  genomeName: '街のサッカー小僧遺伝子',
  setCategoryId: 1,                  // Math.max(現在, これ) に更新
  bonusMoney: 0,                     // 任意
  achievementId: undefined           // 任意
}
```

### 自動進学

`resolveCareerOptions`（4,572行）で、
**その年齢の全進路ゲノムが Lv5 以上 かつ `qolToggles.autoCareerPath` が true** なら、
モーダルを出さずに「unlocked な中で最後のもの」を自動選択する。

### 22歳4月の強制タイムリープ

`categoryId` が一定未満のまま22歳4月を迎えると、
「プロテスト全落ち → トラックに跳ねられる」で強制的に第1周目が終わる（4,893行）。

## 5. ゲノム（`BASE_GENOME_DEF` / 846行・45種）

プレイヤーが直接買うものではなく、**プレイ内容に応じて勝手に育つ実績バッジ**。

```
Lv = floor( def.getStatVal(state) / def.step )   ※ maxLv でクランプ
```

| 種別 | 件数 | 特徴 |
|---|---:|---|
| 通常 | 23 | 例: `striker_dna` = 通算ゴール45点ごとに1Lv（最大5） |
| 体格 | 4 | `isBodyGenome: true`。その体格での勝利数55ごと |
| 進路 | 18 | `isPathGenome: true` / `maxLv: 999` / `archiveAtLv: 5` |

### 進路ゲノムの二段構え

- **Lv1–5**: 成長%ボーナス
- **Lv5超**: 「全上限 +0.25〜0.6 / Lv」のオーバーキャップボーナスに変わる（`pathOvercapBonus` / 2,266行）
- **Lv5到達で図鑑にアーカイブ**される

> 🐞 **成長倍率側に Lv5 クランプが掛かっていない（系統的な書き忘れ）**
>
> 説明文（`effectDesc`）も上限ボーナス側（`computeIndividualStatCaps`）も
> 一貫して `Math.min(5, lv)` でLv5打ち止めにしているのに、
> **`getDrillEffectiveStats` の成長倍率だけ素の Lv を掛けている。**
>
> 該当: 2,486 / 2,487 / 2,515–2,518 / 2,530–2,532 / 2,542 行
> （`jr_abroad_dna`, `world_acad_12_dna`, `jr_elite_dna`, `j_elite_dna`,
> `brazil_ginga_dna`, `spain_cantera_dna`, `regional_jhs_dna`,
> `overseas_wild_dna`, `jfl_hungry_dna`, `university_iq_dna`）
>
> **同じ関数内の `young_pro_dna`（2,492行）だけ正しく `Math.min(5, ...)` になっている。**
> 設計ではなく書き忘れと判断できる。Lv50 なら説明の +20% ではなく +200%。
> 周回を重ねるほど壊れる。

> 🐞 **表記と実値が3倍ずれている2件**
> - `world_acad_12_dna`（1,187行）: 表示 `全上限 +lv*0.5` / 実装 `min(5,lv)*1.5 + max(0,lv-5)*0.5`
> - `galaxy_cantera_15_dna`（1,243行）: 表示 `全上限 +lv*0.6` / 実装 `min(5,lv)*1.8 + max(0,lv-5)*0.6`
>
> 他の進路ゲノムは一致しているので、この2件だけ説明文の書き換え漏れ。

## 7. 引退とタイムリープ

### 引退条件（4,972–4,977行）

```js
isDeclineRetired =
  age >= 36 &&
  (peakRatingReached || 0) > 15 &&
  postDecayRating < peakRatingReached * 0.62;

if ((age >= maxRetireAge || isDeclineRetired) && !isRetired) { … }
```

`maxRetireAge = Math.round(33 + bodyLv * 0.5 + extraLifeBonus)`（2,850行）

延命要素: `iron_body` +0.5/Lv（最大5） / `king_eternal_dna` +0.6/Lv（最大5） /
`secret_veteran_iron` +2 / `fused_eternal_king` +2 / CH5 +3

> ⚠️ ED5「50歳現役」が到達可能かどうかは未検証。上の合計と基礎値から計算すると届かない可能性がある。

### 第1段階転生（タイムリープ / `LEGACY_UPGRADES_DEF` 13種）

引退時に**継承結晶**を得る（`calculateLegacyGain` / 3,291行）。
2x/4x速度解放、才能限界突破（上限+2.0/Lv・最大120Lv）、
タイムリープの記憶（全成長+11%/Lv）、自動化3種、枠拡張など。

### 第2〜第5段階転生（Ascension / `ASCENSION_UPGRADES_DEF` 8種）

`ascensionCount` が 1〜4 で管理される。能力上限に**乗算**が掛かる。

| 段階 | stageMult |
|---|---|
| 第1（通常） | 1.0 |
| 第2 | 1.15 |
| 第3 | 1.4 |
| 第4 | 1.9 |
| 第5 | 2.8 |

解放ゲート: `ascReqCrystalLv = 60 + ascCount * 35`
`minAsc: 4`（第5段階）でのみ買える「宇宙評議会」2種が最終コンテンツ。

### ブレイクスルー（`BREAKTHROUGHS_DEF` 7種 / 1,637行）

一次転生しても消えない中間層。
5倍集中トレ / 全自動AI / 限界突破の極意書 / 超回復150% / 過密日程 / 輪廻の羅針盤（結晶+25%）/ 特性枠+1。

## 10. テストを書く優先順

上から順に、壊れたときの被害が大きい。

1. **`calcBulkPurchase` / `calcBulkSingleResource`** — 依存ゼロの純粋関数。1x/10x/MAX と所持金ちょうどの境界
2. **`computeIndividualStatCaps`** — 年齢リミッターの境界（7/8/11/12/14/15/17/18歳）
3. **`applyStatGrowth`** — 上限ちょうど / 上限超過 / `limit_break_manual` あり・なし
4. **進路ゲノムの Lv5 クランプ** — 🐞 を直す前に現状を固定し、直した後の期待値に差し替える
5. **引退条件** — `age >= maxRetireAge` と `isDeclineRetired` の両方
6. **セーブのマイグレーション** — `LEGACY_SAVE_KEYS` の各バージョンから現行へ
7. **`advanceOneMonth` の進路選択** — 7/12/15/18歳で `pendingModal` が返ること（今回の回帰）

> - `CURRENT_TUTORIAL_VERSION = 12` と `v0_12` は慣習でしか結びついていない

### `pendingModal` は永続化する

進路選択・タイムリープのモーダル要求は `gameState.pendingModal` に積まれ、
**オートセーブにも含める**（3,162行付近）。

一度「一時的なUI要求だから」と除外したが、それは誤りだった。
放置ゲームなのでモーダルが開いたままタブを閉じるのは普通の操作で、
除外すると `triggeredEvents` のフラグだけが立って**進路選択が永久に失われる**。

`pendingModal` が消えるのは、プレイヤーが実際に選択・確定したときだけ:
- `handleSelectCareerPath`（進路を選んだ）
- `handleProceedFromTruckModal`（タイムリープ演出を抜けた）

メインループは `prev.pendingModal` があると時間を進めない。これが二重の安全弁になっている。
