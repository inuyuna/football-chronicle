### 原因1: 成長が線形、必要値が指数

```
baseCap        6.2 → 7.0 → 8.1 → 9.2 → 10.3 …   足し算
カテゴリ必要値  58 → 82 → 125 → 195 → 310 → 500 → 850   掛け算
```

### 原因2: デッドロック

```
カテゴリが上がらない → 結晶が増えない → 強化できない → カテゴリが上がらない
```

結晶の獲得量は `catFactor = (categoryId + 1)^1.3` が支配項。
カテゴリが止まると獲得量も止まる。

### 狙い（4.5倍）には届いていない

理論値は `stageMult 2.5 × divineMult 1.8 = 4.5倍`。実測は2.06倍。

差の原因は**成長率が律速していること**。
`stageMult` も `divine_cap_multiplier` も「能力上限（pool）」に掛かる値で、
上限を引き上げても**33年のキャリアで上限まで育てきれない**。

聖杯32個の使い道も偏っている:
- `divine_cap_multiplier`（上限 +16%/Lv）→ Lv5 で28個消費
- `divine_growth_overdrive`（成長量に乗算）→ Lv1 で3個

**上限より成長率に投資すべき局面なのに、上限に全振りしている。**
計測の購入優先順（`ASCENSION_PRIORITY`）が
「神域・才能器倍率 → 天賦の学習速度」の順になっているため。

### 次に試すこと

1. 購入優先順を変えて測る（成長率を先に買う）
2. それでも足りなければ `divine_growth_overdrive` の効果かコストを調整
3. 「上限は上がったが育てきれない」構造自体を見直す
   （キャリアの年数を延ばす / 成長の基礎量を上げる）

## 2026-11-20 ⑫ 継承結晶を「到達度」ベースに作り替えた

本人の2つの指摘が同じ根だった:
> 「転生してすぐタイムリープした方が結晶効率がいいという構造になっちゃってる」
> 「キャリア年数は結晶購入で伸びていく仕組みに。30歳以降は鈍化して早期引退のインセンティブに」

旧式:
```
(catFactor*1.5 + 勝利*0.25 + ゴール*0.2 + アシスト*0.18 + √rating*0.8) × ageFactor
```
- **試合数に比例** → 長く現役を続けるほど得（48〜63歳まで引っ張るのが最適）
