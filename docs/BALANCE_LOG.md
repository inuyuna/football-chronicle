JFL（125）にすら12周で届かない。この傾きだと海外（850）は96周目あたり。

### 原因1: 成長が線形、必要値が指数

```
baseCap        6.2 → 7.0 → 8.1 → 9.2 → 10.3 …   足し算
カテゴリ必要値  58 → 82 → 125 → 195 → 310 → 500 → 850   掛け算
```

### 原因2: デッドロック

```
カテゴリが上がらない → 結晶が増えない → 強化できない → カテゴリが上がらない
```

結晶の獲得量は `catFactor = (categoryId + 1)^1.3` が支配項。
カテゴリが止まると獲得量も止まる。

### 後半の律速は「結晶の経済」

上限突破（`cap_breaker`）が両方とも **Lv13 で止まっている**。
結晶残も常に数十個。つまり毎周、結晶を使い切っても1〜2Lvしか上がらない。

```
cap_breaker のコスト = 10 × 1.15^Lv
  Lv13 →    61
  Lv20 →   164
  Lv30 →   662
  Lv60 → 43,000
  Lv120 → 最大Lv。到達には累計で天文学的な結晶が要る
```

一方の獲得量は1周あたり60〜230程度。
**つまり `cap_breaker` の最大120Lv は事実上、到達不能な設定になっている。**

効果も `+2.0/Lv` 固定なので、Lv13 = 全上限 +26 にしかならない。
カテゴリの必要値が850、1500と伸びていく中では焼け石に水。

転生前の最高は 627（周回11）。転生後、**9周かけて 875**。
カテゴリは J1 → 欧州中堅 の **1段だけ**。

本人の意図は

>   **完全無双**できるようになる段階」

なので、第2転生で「桁が変わる」必要がある。実際は +40% しかない。

### 内訳（なぜ +40% しか出ないか）

| 要素 | 値 | 効果 |
|---|---|---|
| 聖杯の獲得 | **5個** | `Math.max(1, floor((legLvSum - 40)/14) + catBonus + genBonus)`。解放条件を Lv28 に下げたので `(28-40)/14 = -1` と主要項が負になる |
| `divine_cap_multiplier` | **Lv1** | baseCost 3 / **growth 1.85**。聖杯5では Lv1 が限界（累計 3→8→18…）。効果は +16%/Lv |
| `stageMult`（段階倍率） | **1.15** | 第2段階の倍率。旧値は 1.15 / 1.4 / 1.9 / 2.8 |

合計 `1.15 × 1.16 ≒ 1.33`。実測の1.4倍とほぼ一致する。

**つまり第2転生＝ハードリセットの見返りが、誤差の範囲しかない。**

### ⑥ で試す修正

| 箇所 | 旧 | 新 |
|---|---|---|
| 聖杯の獲得式 | `max(1, floor((Lv-40)/14) + (cat-10)*2 + gen/3)` | `max(3, floor(Lv/2) + (cat-8)*4 + gen/2)` |
| `stageMult` | 1.15 / 1.4 / 1.9 / 2.8 | **2.5 / 7.0 / 20 / 60**（1段階あたり約2.8倍） |
| `divine_cap_multiplier` の growth | 1.85 | **1.35** |

Lv28 / cat11 / gen12 なら聖杯は 14 + 12 + 6 = **32個**。
growth 1.35 なら Lv5 前後まで買えるので上限 +80%。
段階倍率 2.5 と合わせて **約4.5倍**になる見込み。

### 狙い（4.5倍）には届いていない

理論値は `stageMult 2.5 × divineMult 1.8 = 4.5倍`。実測は2.06倍。

差の原因は**成長率が律速していること**。
`stageMult` も `divine_cap_multiplier` も「能力上限（pool）」に掛かる値で、
上限を引き上げても**33年のキャリアで上限まで育てきれない**。

聖杯32個の使い道も偏っている:
- `divine_cap_multiplier`（上限 +16%/Lv）→ Lv5 で28個消費
- `divine_growth_overdrive`（成長量に乗算）→ Lv1 で3個

**上限より成長率に投資すべき局面なのに、上限に全振りしている。**
計測の購入優先順（`ASCENSION_PRIORITY`）が
「神域・才能器倍率 → 天賦の学習速度」の順になっているため。

### 次に試すこと

1. 購入優先順を変えて測る（成長率を先に買う）
2. それでも足りなければ `divine_growth_overdrive` の効果かコストを調整
3. 「上限は上がったが育てきれない」構造自体を見直す
   （キャリアの年数を延ばす / 成長の基礎量を上げる）
